엔트리 바이브코딩 시작하기

엔트리 바이브코딩은 만들고 싶은 게임을 말로 설명하고, AI 코딩 도우미와 함께 엔트리 작품을 만드는 방법입니다.

Codex, Claude Code 등 파일을 만들고 명령을 실행할 수 있는 AI 코딩 도우미에게 저장소 링크와 아래 프롬프트를 주세요. 엔트리 작품 파일(.ent) 제작과 실제 실행 결과 확인을 요청할 수 있습니다.

저장소: github.com/205sla/entry-vibe-coding

사용법 영상 준비물 환경 준비 게임 만들기 자주 묻는 질문 문제 해결 안내 기준·출처

영상으로 따라 하기

무료 GPT로 엔트리 바이브코딩 하는 법 — AI 코딩 도우미로 엔트리 작품을 만드는 과정을 소개하는 사용법 영상입니다.

준비물

  • 컴퓨터 — Windows, macOS, Linux 모두 됩니다.
  • Node.js — 22 버전 권장(최소 18.18).
  • git — 저장소를 받고, 나중에 업데이트(git pull)할 때 씁니다.
  • 인터넷 — 처음 설치할 때 엔트리 엔진 등을 내려받습니다(수 분).
  • AI 코딩 도우미 — 명령을 직접 실행할 수 있는 것(Codex, Claude Code 등).

Node.js와 git은 없어도 시작할 수 있습니다. 아래 환경 준비 프롬프트가 AI에게 먼저 설치 여부를 확인하게 하고, 이미 있으면 그대로 쓰고 없을 때만 설치하게 합니다. 미리 설치해 두면 준비 시간이 짧아집니다. 압축 해제에는 tar, 실행 검사에는 Playwright Chromium과 운영체제별 브라우저 실행 라이브러리도 필요합니다. 자세한 조건은 새 환경 설치 문서에서 확인하세요.

1 환경 준비

빈 폴더를 AI 코딩 도우미의 작업 폴더로 열고 아래 프롬프트를 붙여 넣으세요. 설치와 확인 검사까지 알아서 진행하고, 무엇이 통과했는지 보고합니다.

이미 환경 준비를 마친 폴더라면 처음부터 다시 설치하지 않아도 됩니다.

환경 준비 — 빈 폴더에서 링크만 줄 때 
https://github.com/205sla/entry-vibe-coding 저장소로 엔트리 작품을 만들 수 있게 이 PC에 환경을 준비해줘.

1. 먼저 node -v, npm -v, git --version 으로 이미 설치된 것을 확인해.
   - Windows PowerShell에서 npm·npx가 "스크립트를 실행할 수 없으므로"로 막히는 건 설치가 안 된 게 아니야.
     npm.cmd·npx.cmd로 실행해(이후 단계도 같아).
   - 있는 건 그대로 쓰고, 없는 것만 설치해(Node는 22 권장). 이미 있는 프로그램은 지우거나 바꾸지 마.
     Node가 18.18보다 낮으면 바꾸기 전에 나에게 물어봐.
   - 새로 설치했다면 AI 도구 안에서만이 아니라 내가 새 터미널 창을 열었을 때도 그 명령들이 되게 해 줘.
2. 저장소를 이 폴더에 클론하고, 클론한 폴더의 AGENTS.md를 먼저 읽어. 거기서 안내하는 CLAUDE.md의
   "환경 준비"를 그대로 따라 해.
3. 순서는 npm install → npm run setup → npx playwright install chromium 이야.
   Chromium은 꼭 npm install 뒤에 설치해.
   이 세 명령은 인터넷 접속과 작업 폴더 밖 캐시(npm 캐시, 검사용 브라우저 폴더) 쓰기가 필요해.
   명령마다 권한 승인이 필요한 환경이면 처음부터 그 권한을 요청해서 실행해.
4. 엔트리 엔진(entryjs)은 절대 빌드하지 마. setup이 이미 빌드된 파일을 받아 온다.
   setup이 실패하면 오류 메시지대로 조치한 뒤 다시 실행해.
5. 설치가 끝나면 아래로 확인해:
   - npm run test:smoke
   - npx playwright test -g "loads with no page errors"   (편집기가 실제로 뜨는지)
   - node tools/play-check.mjs tests/fixtures/bounce-ball.ent   (예제 게임이 실제로 움직이는지)
6. 한국어로 보고해줘: Node·npm·git 버전과 새로 설치한 것, 통과한 단계, 실패했거나 못 한 단계와 그 이유,
   편집기 여는 방법(npm start → http://localhost:3000). 게임은 아직 만들지 마.
저장소를 이미 받아서 그 폴더를 열었다면 (짧은 판)

2 게임 만들기

환경 준비가 끝난 같은 대화에서 만들고 싶은 게임을 말하세요. 아래는 예시입니다. 조작 방법, 점수, 끝나는 조건을 적어 주면 결과가 훨씬 좋아집니다.

게임 요청 — 예시: 사과 받기 
사과 받기 게임 만들어줘. 방향키로 바구니를 좌우로 움직이고, 떨어지는 사과를 받으면 점수 +1, 3개 놓치면 게임 끝.
CLAUDE.md의 제작 사이클과 검증 사다리를 따르고, play-check 보고가 내 요청과 맞는지 비교해서 알려줘.

만든 작품은 games/<이름>/<이름>_001.ent처럼 번호가 붙어 저장되고, 고칠 때마다 _002, _003으로 새 파일이 생깁니다. 직접 보려면 npm start를 실행한 뒤 브라우저에서 http://localhost:3000을 열어 .ent 파일을 불러오세요.

엔트리 바이브코딩, 자주 묻는 질문

엔트리 바이브코딩은 무엇인가요?

만들고 싶은 게임을 말로 설명하고 AI 코딩 도우미와 함께 엔트리 작품을 만드는 방법입니다. 이 안내에서는 205sla/entry-vibe-coding 저장소의 도구로 작품 파일을 만들고, 로컬 엔트리 편집기에서 불러와 실행하는 과정을 다룹니다.

어떤 AI 코딩 도우미가 필요한가요?

PC의 작업 폴더에서 파일을 읽고 쓰며 터미널 명령을 실행할 수 있는 도구가 필요합니다. Codex, Claude Code 등이 해당합니다. 작업 폴더를 연 뒤 저장소 링크와 환경 준비 프롬프트를 전달하면 됩니다. 설치·검사 과정에서 실행 권한이나 인터넷 접속 승인이 필요할 수 있습니다.

처음 설치할 때 무엇이 필요한가요?

컴퓨터, Node.js·npm, Git, tar와 인터넷 연결이 필요합니다. 이 저장소는 Node.js 22를 권장하며 최소 버전은 18.18입니다. 실행 검사에는 Playwright Chromium도 필요하고, npm install 다음에 설치합니다. Linux에서는 브라우저 실행에 필요한 시스템 라이브러리를 추가로 설치해야 할 수 있습니다.

근거: 새 환경 설치 조건

새 작품을 만들 때마다 환경 준비를 다시 해야 하나요?

아니요. 한 번 환경 준비를 마친 작업 폴더에서는 반복할 필요가 없습니다. 작품 제작에 필요한 라이브러리와 엔트리 편집기 파일이 그 폴더에 설치되어 남아 있기 때문입니다.

다음에 다른 작품을 만들 때도 AI 코딩 도우미에서 같은 폴더를 열고 바로 게임 제작 프롬프트를 입력하세요. 새 대화를 시작했다면 “이 폴더의 AGENTS.md와 CLAUDE.md를 읽고 새 작품을 만들어줘”라고 함께 알려 주세요.

다른 컴퓨터나 새 폴더에 저장소를 새로 받았다면 그곳에서는 환경 준비가 필요합니다. 기존 폴더도 설치 파일을 지웠거나 업데이트로 필요한 파일이 달라진 경우에는 다시 점검해야 합니다.

근거: 환경 준비 — 처음 한 번 · 설치와 작품 제작 방법

어떤 파일이 만들어지고, 어디에서 실행하나요?

결과물은 엔트리 작품 파일인 .ent입니다. games/<이름>/<이름>_001.ent처럼 저장하며 수정본은 번호를 늘려 별도 파일로 만듭니다. npm start를 실행하고 http://localhost:3000의 로컬 편집기에서 파일을 불러와 실행·수정·저장할 수 있습니다.

근거: 프로젝트 사용 설명 · 작품 파일 저장 규칙

엔트리 엔진을 직접 빌드해야 하나요?

직접 빌드할 필요가 없습니다. npm run setup이 이미 빌드된 엔트리 엔진과 편집기에 필요한 파일을 구성합니다. 설치가 실패하면 오류가 난 다운로드나 설정을 확인한 뒤 다시 실행합니다.

근거: 환경 준비·엔진 사용 규칙

AI가 만든 게임이 제대로 작동하는지 어떻게 확인하나요?

파일 구조 검사에 이어 편집기에 불러와 실행하는 검사까지 진행합니다. node tools/play-check.mjs <.ent 파일 경로>로 움직임과 키 입력 반응을 확인하고, 작품별 검사에서 점수·종료 조건 등이 요청과 맞는지 확인합니다. AI에게 통과한 검사와 실행하지 못한 검사를 구분해 보고하도록 요청하세요. 직접 확인하려면 로컬 편집기에서 작품을 열고 실행 버튼을 누르면 됩니다.

근거: 제작 사이클·검증 사다리

막힐 때

PowerShell에서 "이 시스템에서 스크립트를 실행할 수 없으므로…"가 나와요

Windows의 실행 정책 때문입니다. 설정을 바꿀 필요 없이 npm 대신 npm.cmd, npx 대신 npx.cmd로 실행하면 됩니다. 위 프롬프트에 이미 들어 있어서 AI가 알아서 바꿉니다.

AI가 명령 실행이나 인터넷 접속을 허용할지 물어봐요

처음 설치할 때 npm, GitHub, 엔트리 사이트에서 파일을 내려받고 작업 폴더 밖(npm 캐시, 검사용 브라우저 폴더)에 저장해야 해서 허용이 필요합니다. Node.js나 git을 새로 설치할 때도 허용을 묻습니다. 허용하지 않으면 설치가 중간에 멈춥니다.

설치(setup)가 중간에 실패했어요

npm run setup은 여러 번 실행해도 안전합니다. 오류 메시지대로 조치한 뒤 다시 실행하게 하세요. 엔트리 엔진을 직접 빌드하려고 하면 멈추게 하세요 — 빌드는 필요 없습니다.

Chromium(검사용 브라우저) 설치가 안 돼요

작품 파일은 그래도 만들어집니다. 다만 실제로 실행해 보는 검사를 못 하므로, AI가 "런타임 검증 미수행 — 사유"를 보고에 적게 되어 있습니다. 이때는 npm start로 편집기를 열어 직접 실행해 보세요.

검사 결과가 다 나왔는데 명령이 끝나지 않아요

통과·실패 결과가 모두 출력됐다면 그 명령은 멈춰도 됩니다. 일부 환경에서 검사 도구가 결과를 출력한 뒤 종료되지 않는 경우가 있습니다. AI에게 "출력된 결과로 판단하고 다음으로 넘어가"라고 하세요.

예전에 받아 둔 저장소 폴더가 있어요

새 기능과 수정이 반영되도록 먼저 git pull을 실행하세요. git 명령을 찾을 수 없다고 나오면 git을 설치하거나, AI에게 "이 폴더에서 git pull 해줘"라고 부탁하세요.

링크를 줬는데 AI가 문서를 안 읽고 바로 만들어요

저장소 첫 화면 주소(https://github.com/205sla/entry-vibe-coding)를 줬는지 확인하세요. 그리고 "AGENTS.md를 먼저 읽고 그대로 따라 해줘"를 한 줄 덧붙이면 대부분 해결됩니다.
